# Dataset consolidation guide

This pipeline creates **research candidates only** under `data/annotation/imported_candidates/`. It does not import into PostgreSQL, write to the source workbooks, establish truth, or merge products. Every source-provided claim/reality description remains an assertion with pipeline verification status `unverified`; annotation records carry `annotation_status: pending_review` and `verification.status: unverified`.

An unmatched checklist row is retained as a separate unresolved candidate.

## Reproduce

The output directory must not exist or must be empty. The command refuses to overwrite it. `openpyxl` is used because it is already available; the script does not install dependencies. Fix the import timestamp to make rerun outputs deterministic for identical workbooks and script version:

The fixed `--import-timestamp` is an operator-supplied reproducibility value. It is not a source-workbook collection date, package-evidence date, or reviewer date; source snapshot/retrieval dates remain `unknown` unless the source supplies them.

```bash
python scripts/consolidate_product_datasets.py \
  --input /Users/snehajuyal/Downloads/misleading_indian_food_products.xlsx \
  --input /Users/snehajuyal/Downloads/indian_packaged_food_annotation_records.xlsx \
  --input /Users/snehajuyal/Downloads/master_verified_food_corpus.xlsx \
  --out-dir data/annotation/imported_candidates \
  --import-timestamp 2026-11-16T00:00:00Z
```

For a fresh rerun, choose another output directory or archive the generated candidate release first. Candidate IDs are deterministic from workbook basename, worksheet, Excel row and source record identifier; they do not depend on import timestamp. Output is create-only to protect prior reviews.

Each imported row also has a SHA-256 `source_row_fingerprint` over its original headers and cell values. It is stored separately from the candidate ID. To compare a fresh candidate release with a prior JSONL without changing that prior release, pass `--compare-to` pointing to its `consolidated_annotation_candidates.jsonl`; `source_row_changes.csv` reports same-ID rows whose fingerprints differ. The comparison reads the prior file only.

Run the review and validation tools:

```bash
python scripts/validate_annotation_dataset.py \
  data/annotation/imported_candidates/consolidated_annotation_candidates.jsonl \
  --report data/annotation/imported_candidates/annotation_validation_report.json
```

## Outputs

| File | Contents |
|---|---|
| `consolidated_annotation_candidates.jsonl` | One candidate per product-sheet row, including original source cells, whitespace-normalized values, candidate annotation fields, source locations, unresolved status, duplicate review and research assertions. |
| `consolidated_product_candidates.csv` | Review-friendly flattened view with original and normalized fields plus source rows. |
| `consolidated_product_candidates.xlsx` | Review workbook with Candidates, Duplicates, Category Review and Claim Queue sheets. |
| `duplicate_candidates.csv` | Pairwise exact/close same-brand candidate matches and explicitly distinct Bhujia variants. None are confirmed or merged. |
| `category_mapping_review.csv` | Rows with candidate category mappings or unresolved category mapping. All mappings remain review-required. |
| `claim_verification_queue.csv` | Source claims, alleged concerns, reported ingredient/reality text and regulatory statements; pipeline status always `unverified`. |
| `malformed_suspicious_records.csv` | Misaligned or missing-name rows with original cells. Knorr’s apparent shift is flagged, never repaired. |
| `source_row_changes.csv` | Same-ID source-row fingerprint changes against `--compare-to`; header-only when no comparison file is supplied. |
| `annotation_validation_report.json` | Output of the existing annotation schema v1 validator, generated by the importer after writing candidate JSONL. |
| `import_manifest.json` | Input file hashes, per-sheet row counts, IDs/version, duplicate/category/claim counts, output names, source-row comparison summary and validator report pointer. |

## Review rules

- Original cell values live in `source_fields[]` with one-based column index and original header (empty headers receive a display name such as `column_8`; cells beyond the detected header receive positional names such as `column_9` and a null `original_header`); normalized whitespace lives separately. All row cells are included in the source-row fingerprint and preserved in JSONL and the review CSV/XLSX.
- `source_row_fingerprint` hashes the ordered original header/value pairs; candidate IDs remain based on workbook/sheet/row/source identifier and stay stable when row contents change. Legacy comparison reconstructs a fingerprint from preserved source fields and may not recover blank raw headers.
- Workbook, worksheet and Excel row number are preserved in `source_locations[]` and source records.
- Workbook-asserted “verified” labels are retained under `research_assertions.source_claimed_verification_status`; they never set the annotation’s verification status.
- Workbook “actual ingredients / reality” is not treated as package transcription. `label.ingredients_original` remains missing until a package/manufacturer source is inspected.
- Barcode, pack size, nutrition, serving, allergens and product image remain explicitly missing unless actually provided with suitable evidence. The supplied sheets do not contain physical package evidence or GTIN/pack values.
- Duplicate matching requires exact brand plus exact normalized name, or a high same-brand name similarity candidate. Distinct descriptors on Bhujia variants are surfaced as distinct-variant relationships. Every decision remains for human review; no records are combined.
- Category mapping distinguishes a candidate mapping from an unresolved mapping. Spices remain unresolved because the current taxonomy has no spices leaf; they are not silently moved into staples.
- Input license and attribution are marked `unknown` where workbook metadata did not provide them. Resolve permissions before redistributing or training on this material.
